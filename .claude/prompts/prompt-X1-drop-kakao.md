## 목표

**카카오톡을 이 제품에서 걷어낸다.** 스키마·타입·화면 전부에서.

이건 기능 축소가 아니라 **거짓을 지우는 일**이다. 지금 코드와 화면은
카카오톡으로 고객 문의를 받을 수 있는 것처럼 되어 있는데, 그럴 수 없다.

## 왜 — 조사 결과

`AGENTS.md`의 도메인 제약에 적혀 있고, 근거는 이렇다.

- **인바운드 불가.** LGU+ 메시지허브 MO의 `moType`은 `SMSMO`·`MMSMO`·`RCSMO`
  뿐이고 카카오가 없다. 고객이 카톡으로 보낸 문의는 우리에게 도달하지 않는다
- **자유 텍스트 발송 불가.** 알림톡은 사전 승인된 템플릿만 보낼 수 있다.
  상담원이 입력한 문장을 그대로 카톡으로 보내는 건 불가능하다
- **우회로 없음.** 카카오 V2 채널 API는 아웃바운드 템플릿 관리 전용이고,
  카카오 디벨로퍼스로도 안 된다 — 비즈니스 메시지는 공식 파트너사를 통해서만
  연동되고 상담톡은 별도 계약이 필요하다

즉 **현재 계약으로 카톡은 어느 방향으로도 동작하지 않는다.** 남겨두면
"되는 줄 알았는데 안 되는" 기능이 되고, 이후 슬라이스가 카톡 수신 경로를
만들려 들게 만든다.

나중에 상담톡 파트너사와 계약하면 되살린다. 그때는 **컬럼과 값을 추가**하는
방향이라 싸다. 지금 남겨두고 나중에 지우는 것보다 훨씬 낫다.

## 남길 것과 지울 것

**지운다**

- `Channel` 타입 (`'카톡' | '문자'`) — 값이 하나뿐인 유니온은 모델링할 이유가 없다
- `conversations.channel` 컬럼 — 전부 같은 값이 될 컬럼이다. 아웃바운드 라우팅에도
  쓰이지 않는다(자유 텍스트는 언제나 SMS/LMS로 나간다)
- 목록의 채널 필터 드롭다운, 행의 채널 배지
- 사무소 설정 "채널 연동" 카드의 카카오톡 행
- 그 밖에 화면에 보이는 `카톡`·`카카오톡` 표기 전부

**남긴다**

- `messages.channel` — **이건 진짜다.** 본문 바이트 길이에 따라 SMS인지 LMS인지
  실제로 갈리고, 수신은 SMS인지 MMS인지 갈린다. 건별로 다른 값이 들어간다.
  `SEND_CHANNELS`에서 `'카톡'`만 빼고 `['SMS','LMS','MMS']`로 좁혀라
- 발신 말풍선의 채널 표기 — `messages.channel` 값을 그대로 보여준다

## 찾는 방법

아래는 내가 아는 지점이지만 **전부가 아닐 수 있다.** `카톡`·`카카오`·`Channel`·
`channel`로 저장소 전체를 grep해서 스스로 확인해라.

- `shared/domain.ts` — `CHANNELS`, `SEND_CHANNELS`
- `migrations/0001_init.sql` — `conversations.channel`, `messages.channel`의 CHECK
- `tests/schema.test.ts` — 위 배열을 순회해 CHECK와 대조하는 테스트
- `src/types.ts` — `Channel` 재수출, `ChannelFilter`, `Toast.channel`
- `src/theme.ts` — `CHANNEL_BADGE`, `CHANNEL_FULL`, `CHANNEL_DOT`
- `src/data/seed.ts` — 카톡 대화 3건
- `src/state/inbox.ts` — `chan` 상태, `setChan` 액션

- `src/components/` — `ConversationList`(필터·배지), `ChatPane`(헤더), `Toast`,

## 지우면 안 되는 것 — 주의

grep에 걸리지만 **채널 모델이 아닌 것**들이 있다. 기계적으로 지우지 마라.

**고객 메모 본문**에 "카톡"이라는 단어가 들어 있다:

```
src/data/seed.ts  "전화보다 카톡 선호. 오후 2시 이후 연락 요망."
src/data/seed.ts  "1인 스튜디오, 연매출 8천 예상. 카톡 응답 빠름."
```

이건 상담원이 남긴 **메모의 내용**이다. 실제 세무사무소에서 "이 고객은 카톡을
선호한다"는 메모는 얼마든지 있을 수 있다. **그대로 둬라.**

`src/index.css`의 `--color-kakao-fg` / `--color-kakao-bg`는 원본 디자인에서 온
**색상 토큰**이다. 쓰이지 않게 되면 지워도 되지만, 다른 곳에서 참조하는지
확인하고 판단해라. 판단이 애매하면 남겨두고 보고해라 — 색 하나 남는 것보다
잘못 지워서 화면이 깨지는 게 나쁘다.

`src/state/inbox.ts`의 발신 시각 스탬프는 지금 채널로 분기한다:

```ts
return `${channel === '카톡' ? '채널톡' : 'SMS'} · ${clockLabel(now)}`
```

카톡이 사라지면 분기가 무의미해진다. 다만 이 함수는 나중에 `messages.channel`의
실제 값(SMS/LMS)을 쓰도록 바뀔 자리다. **지금은 분기만 걷어내고 단순화해라.**

## 판단이 필요한 지점

**RCS 수신을 어떻게 할지는 정하지 마라.** MO에 `RCSMO`가 있지만 우리는 RCS를
구현하지 않는다. `messages.channel`에 RCS를 넣을지는 수신 어댑터 슬라이스의
문제다. **지금 넣지도 말고, 넣어야 한다고 판단되면 `ask`로 물어라.**

**목록 행에서 채널 배지를 없애면 자리가 빈다.** 어떻게 정리할지는 네가 판단해라.
원본 디자인(`design/prototype.dc.html`)을 참고하되, 없어진 요소 자리에 억지로
뭘 채워 넣지는 마라.

**사무소 설정의 "채널 연동" 카드**는 카카오톡 행만 빼고 문자 발신번호와
LGU+ 메시지허브는 남긴다. 카드 제목이 "채널 연동"인 채로 남아도 어색하지 않은지
보고, 어색하면 문구를 조정해라.

## 수용 기준

1. `npm run check` 통과
2. **채널 모델로서의** 카톡이 0건. 확인 방법:

   ```sh
   grep -rn "카톡\|카카오" src/ shared/ worker/ migrations/ tests/
   ```

   남아도 되는 것은 **고객 메모 본문 두 줄뿐**이다(위 "지우면 안 되는 것" 참조).
   그 외에 하나라도 남으면 이유를 보고해라. `design/`과 `AGENTS.md`는 제외한다
3. `grep -rn "Channel" src/ shared/` 결과에 `SendChannel` 외의 채널 타입이 없다
4. 마이그레이션에서 `conversations.channel` 컬럼이 사라졌고, 스키마 테스트가
   여전히 통과
5. `messages.channel` CHECK가 `('SMS','LMS','MMS')`이고 `shared/domain.ts`의
   `SEND_CHANNELS`와 **글자 그대로 일치**
6. **앱이 실제로 동작한다** — `npm run dev`로 띄워 목록·대화·설정 화면이
   깨지지 않는지 확인해라. 스크린샷을 남길 수 있으면 남겨라
7. 기존 대화·메시지 표시가 정상 (seed 데이터가 전부 문자로 바뀌었을 것이다)

## 커밋 메시지에 남길 것

**왜 지웠는지**를 반드시 적어라. 이 커밋을 나중에 보는 사람이 "왜 카톡을 뺐지,
다시 넣어야 하나" 하고 되돌리려 들 수 있다. 조사 결과(인바운드 불가·자유 텍스트
불가·별도 계약 필요)와 **되살릴 때는 추가 방향이라 싸다**는 점을 남겨라.
