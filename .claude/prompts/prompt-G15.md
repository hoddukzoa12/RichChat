# G15 — 발신 배지 `전송중`을 `발송됨`으로 표기한다

`AGENTS.md`를 먼저 읽고 그 원칙을 따라라.

## 왜

업무폰 발신의 도달 확인(`sms:delivered`)은 수신자 통신사가 돌려줘야 오는데
**대부분 안 돌려준다** (운영 실측: 13건 중 1건). 게이트웨이 앱 자체가
`Sent`까지만 본다. 즉 `전송중`이 사실상의 최종 상태인데, 지금 화면은
"곧 완료로 바뀐다"고 암시한다 — 사용자가 상태 관리가 고장 났다고 오해했다.

사용자 승인: 표기를 **`발송됨`** 으로 바꾼다.

## 무엇을 하는가

**표시 문구만 바꾼다.** DB 값·와이어 타입·전이 로직·API는 그대로다 —
`delivery_status`의 `'전송중'` 리터럴은 `shared/domain.ts`·D1 CHECK와 묶여
있으니 건드리지 마라.

지금 `src/components/ThreadPanel.tsx:225` 부근이 상태 값을 그대로 문구로
렌더한다. `src/theme.ts`에 **`Record<DeliveryStatus, …>` 표시 매핑**을 두고
(AGENTS.md §2 — 닫힌 집합은 Record로, 값이 늘면 컴파일러가 잡게) 거기서
`전송중 → '발송됨'`만 바꿔라. 다른 상태의 문구는 지금 그대로다.

배지 색상 클래스는 유지해라. 문구 슬라이스다.

`전송중`을 화면에 보여주는 곳이 ThreadPanel 말고 더 있는지 grep으로 확인하고,
**사용자에게 보이는 모든 곳**이 `발송됨`으로 나오게 해라.

## 건드리지 마라

`worker/`, `shared/`, `migrations/` — **다른 슬라이스가 worker를 고치는 중이다.**
`AGENTS.md`·`CLAUDE.md`·계획서 수정 금지.

## 수용 기준

1. `npm run check` 통과
2. **실제 렌더에서** 발신 말풍선 배지가 `발송됨`으로 보인다 (컴포넌트 테스트
   또는 브라우저 확인 — 문자열 치환이 아니라 렌더 결과로 확인해라)
3. `수신`·`대기`·`접수`·`완료`·`실패` 표기는 변화 없다
4. DB·API·`shared/`에 `발송됨` 리터럴이 **한 곳도 없다** — 표시 계층에만 있다
5. `python3 .claude/scripts/dead-exports.py` · `positional-consts.py` ·
   `unwired-routes.py` 통과
6. 커밋하고 `origin/hoddukzoa12/g15-sent-label`에 푸시한 뒤 해시를 보고해라.
   **배포하지 마라.**
