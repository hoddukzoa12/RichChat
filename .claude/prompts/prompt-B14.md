## 목표

**사무소 설정과 직원 관리.** 관리자만 접근한다.

```
GET   /api/office/settings
PATCH /api/office/settings
GET   /api/office/members
POST  /api/office/invites
```

## 지금 무엇이 틀렸는가

**`isAdmin: true`가 클라이언트에 하드코딩돼 있다.** 서버가 권한을 전혀 안 본다.

그리고 초대 입력이 `@`로 시작하는 이메일에 **크래시한다** (`'@x.com'.split('@')[0]`이
빈 문자열이 되는 경로).

## 반드시 지킬 것

### 권한은 SQL에서 강제한다

응용 코드의 `if`로만 막지 마라. **쿼리 자체가 비관리자를 못 통과시켜야** 한다.

```sql
UPDATE office_settings SET ... WHERE office_id = ?
  AND EXISTS (SELECT 1 FROM users WHERE id = ? AND role = '관리자')
```

**403은 `meta.changes === 0`으로 판정**한다.

역할은 **세션에서 파생된 것**을 쓴다. 요청 본문의 역할 주장을 믿지 마라.

수용 기준은 "403이 떴다"가 아니라 **"403이면서 행이 안 바뀌었다"**이다.
403을 반환하면서 실제로는 수정된 구현이 통과하면 안 된다.

### 초대 — 크래시부터 막아라

`'@x.com'`, `''`, `'a@'`, `'a@@b.com'`, 공백만, 아주 긴 문자열.
**전부 400이어야 하고 크래시하면 안 된다.**

`split('@')[0]`으로 이름을 만드는 식의 파싱을 하지 마라. 그게 지금 결함이다.

초대는 `users`에 `status='초대'`로 행을 만든다. `ux_users_email`이 있으므로
**이미 있는 이메일은 중복 생성되지 않는다** — 그 실패를 500으로 흘리지 말고
409나 200(멱등)으로 번역해라. 어느 쪽이든 **행이 두 개 되면 안 된다.**

이미 `활성`인 사람을 다시 초대하면 **`status`를 `초대`로 되돌리지 마라.**
멀쩡히 일하는 직원이 로그인을 잃는다.

`works_sub`는 여기서 건드리지 마라 — 최초 로그인(B5)이 확정한다.

### 자기 권한을 못 뺏고 못 준다

관리자가 자기 역할을 내리거나 남에게 관리자를 주는 경로를 **이 슬라이스에서
만들지 마라.** 요청받지 않았고, 마지막 관리자가 자기 권한을 내리면 사무소가
잠긴다.

역할 변경이 필요해 보이면 구현하지 말고 `ask`로 물어라.

### 멤버 목록

`GET /api/office/members`는 팀 화면이 쓴다. **비관리자도 볼 수 있어야 한다** —
담당자 배정 UI가 이 목록을 쓰기 때문이다.

읽기는 열고 쓰기만 관리자로 막아라. 다만 **비관리자에게 민감한 필드를 주지
마라** (초대 상태 등은 관리자만).

목록에 `works_sub`나 세션 정보를 절대 넣지 마라.

### 설정 값

`office_settings`에 `export_log`·`retention_years`가 있다. `updated_by`를
세션 사용자로 기록해라.

`retention_years`에 범위 검증을 걸어라. 0이나 음수, 터무니없이 큰 값이
들어가면 보존 정책이 무의미해진다.

## 수용 기준

1. `npm run check` 통과
2. 쿠키 없이 호출 → 401
3. **비관리자 PATCH → 403 그리고 `office_settings` 행이 안 바뀜.**
   응답 코드만 보지 말고 DB를 직접 읽어 확인해라
4. 관리자 PATCH → 반영되고 `updated_by`가 기록된다
5. **`'@x.com'` 초대 → 400. 크래시 아님**
6. `''`·`'a@'`·`'a@@b.com'`·공백·초장문 → 전부 400, 크래시 없음
7. 같은 이메일 2회 초대 → **`users` 행이 1개**
8. **이미 `활성`인 사용자를 재초대 → `status`가 `활성` 그대로**
9. 비관리자도 `GET /api/office/members` 가능
10. 멤버 응답에 `works_sub`·세션 토큰이 **없다**
11. `retention_years`에 0·음수·비정상 값 → 400
12. 변경 1건당 이벤트 1건, 403일 때 이벤트 0건

## 만들지 말 것

- 역할 변경 — 위 참고. 필요하면 `ask`
- 초대 메일 발송 — 범위 밖이다. 행만 만든다
- 로그인·OIDC — B5 소유
- 내 프로필·내 설정 — B13 소유
- 프론트엔드(`src/`), `migrations/`, `wrangler.jsonc` 수정
