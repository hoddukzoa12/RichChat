## 목표

프론트엔드를 **서버에 연결하는 축**을 놓는다. 화면 이관은 다음 슬라이스들이 한다.

1. `src/api/` — fetch 래퍼 + 엔드포인트 모듈 **빈 스텁**
2. 인증 게이트 — 401이면 로그인 화면
3. **`ME` 상수 제거**

## 왜 스텁을 미리 만드는가

F3~F6이 각자 `src/api/endpoints/*`에 자기 것을 채운다. 지금 파일을 다 만들어
두지 않으면 **네 슬라이스가 같은 배럴 파일을 두고 싸운다.**

`src/api/endpoints/`에 `conversations.ts`·`messages.ts`·`customers.ts`·
`notes.ts`·`tasks.ts`·`office.ts`·`me.ts`·`events.ts`를 **빈 스텁으로** 만들고
배럴에서 재수출해라. 그다음 **아무도 배럴을 안 건드린다.**

## 지금 무엇이 틀렸는가 — `ME`

`ME = '박상담'`이 모듈 상수다. 이게 **표시 이름 문자열**인데:

- "내 담당" 필터가 이 문자열로 비교한다
- 메모 작성자 판정이 이 문자열이다
- `isAdmin: true`가 클라이언트 하드코딩이다

`profile.name`은 설정에서 따로 편집된다. **이름을 바꾸면 자기 담당 대화가
자기 필터에서 사라진다.**

신원은 `/api/me`에서 온다. 비교는 **id로** 한다.
`grep -c 'ME' src/components/`가 0이어야 한다 (단어 경계로 정확히 세라 —
`SOME`·`THEME` 같은 단어가 섞이지 않게).

## 반드시 지킬 것

### 401 처리는 한 곳에

fetch 래퍼가 401을 잡아 로그인 화면으로 보낸다. **엔드포인트마다 처리하지 마라.**

로그인 화면에서 `/api/auth/login`으로 보낸다. 개발 중에는 개발 로그인 경로가
있는데 **그 존재를 UI에 노출할지는 서버 응답으로 판단해라** — 클라이언트에
플래그를 박지 마라.

### CSRF

비-GET에 `Origin` 검사가 서버에 걸려 있다. 동일 출처 요청이면 브라우저가
자동으로 실어 보내므로 **헤더를 손으로 만들지 마라.**

쿠키는 `credentials: 'same-origin'`으로 나간다.

### 낙관적 갱신의 토대

모든 변경 요청에 `clientKey`(UUID)를 싣고 서버가 그대로 돌려준다.
리듀서가 **`clientKey` 먼저, 없으면 `id`로** 병합한다.

여기서는 **키를 만들어 싣는 것까지만** 해라. 실제 병합은 F4가 한다.
`crypto.randomUUID()`를 쓴다.

### 스텁은 진짜 비어 있어야 한다

타입만 두거나 `throw new Error('not implemented')`로 둬라.
**가짜 구현을 넣지 마라** — 다음 슬라이스가 그걸 진짜로 착각한다.

### 목 데이터를 지우지 마라

`src/data/seed.ts` 삭제는 **F8 소유**다. 아직 화면이 그걸로 돈다.
여기서 지우면 앱이 죽는다.

### 에러 표시

네트워크 실패와 서버 오류를 구분해 보여줘라. 조용히 삼키면 사용자가 저장된
줄 안다.

## 수용 기준

1. `npm run check` 통과
2. **앱이 실제로 뜬다.** `npm run dev`로 띄워 화면을 확인해라
3. `grep -c '\bME\b' src/components/` = 0
4. `isAdmin`이 `/api/me` 응답에서 온다. 하드코딩 0건
5. 401 응답 → 로그인 화면. 엔드포인트마다가 아니라 **래퍼 한 곳에서**
6. `src/api/endpoints/`에 8개 파일이 있고 배럴에서 재수출된다
7. 스텁 호출 시 **명시적으로 실패**한다 (조용한 성공 없음)
8. 변경 요청에 `clientKey`가 실린다
9. `src/data/seed.ts`가 **그대로 있다**
10. 기존 화면이 여전히 동작한다 — 이 슬라이스는 **축만 놓는다**
