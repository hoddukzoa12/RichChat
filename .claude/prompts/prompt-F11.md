## 목표

**채팅창의 이미지를 클릭하면 크게 본다.**

지금 `src/components/ThreadPanel.tsx`의 `MessageAttachmentView`가
`max-h-64`로 줄여 렌더하고 **클릭해도 아무 일이 안 일어난다.**
고객이 보낸 사업자등록증·영수증을 읽으려면 확대가 필요하다.

## 먼저 읽을 것

- `src/components/ThreadPanel.tsx:70-112` — 지금의 첨부 렌더
- `src/api/endpoints/attachments.ts` — `attachmentUrl(id, 'inline' | 'download')`

**이미지 주소를 새로 만들지 마라.** `attachmentUrl`이 정본이다.
세션 쿠키가 붙는 동일 출처 경로이고, 그래야 링크만 아는 사람이 고객 문서를
열지 못한다.

## 만들 것

이미지를 클릭하면 **큰 화면으로 본다.** 구현 형태는 네가 판단해라.

### 반드시 만족할 것

- **닫는 방법이 명확하다** — `Esc`와 배경 클릭 둘 다 되어야 한다.
  닫기 버튼도 있으면 좋다
- **키보드로 쓸 수 있다.** 열 때 포커스가 안으로 들어가고, 닫으면
  **원래 눌렀던 이미지로 돌아온다**. 뒤 화면으로 탭이 새어나가지 않는다
- **한 메시지에 첨부가 여럿이면 그 안에서 넘길 수 있다.**
  사진 3장짜리가 실제로 있다. 좌우 키로도 되게 해라
- **다운로드**를 큰 화면에서도 할 수 있다
- **모바일에서 동작한다.** 이 앱은 `mobile`/`tablet`/`desktop` 브레이크포인트가 있다
- 큰 이미지가 **화면을 넘지 않는다.** 세로로 긴 사진도 다 보여야 한다

### 하지 말 것

- 새 라이브러리를 넣지 마라. 이 저장소는 의존을 얇게 유지한다
- `contentUrl`이나 R2 주소를 화면에 쓰지 마라 — 인증이 없는 주소다
- 이미지가 아닌 첨부에 뷰어를 붙이지 마라. `isInlineImage`가 이미 가른다
- `대기`·`실패` 상태의 표시를 바꾸지 마라

## 디자인

**원본을 먼저 확인해라.** `design/prototype.dc.html`에 뷰어가 없다면
새로 만드는 것이 맞다 — 사용자가 요청했다. 다만 **색·모서리·그림자를
`src/index.css`와 `src/theme.ts`의 기존 값에서 가져와라.** 새 색을 정하지 마라.

애니메이션을 넣는다면 `prefers-reduced-motion`을 존중해라.

## 수용 기준

**전부 실제로 앱을 띄워서 확인해라.** 렌더 테스트만으로는 부족하다.

1. `npm run check` 통과
2. **앱이 뜨고 이미지를 클릭하면 커진다**
3. `Esc`로 닫힌다
4. 배경을 클릭하면 닫힌다
5. **닫으면 포커스가 눌렀던 이미지로 돌아온다**
6. 첨부가 여럿인 메시지에서 **좌우로 넘어간다**
7. 큰 화면에서 다운로드가 된다
8. 세로로 긴 이미지가 잘리지 않는다
9. 모바일 폭에서도 동작한다
10. `grep -rn "cloudfront\|r2_key" src/`가 **0건**
11. 새 npm 의존이 없다 — `package.json` 변경 0
