## 목표

**대화 상태·보관·라벨 변경을 서버에 저장한다.** `PATCH /api/conversations/:id`

지금 **운영에서 저장이 안 된다.** 사용자가 `미처리`를 `처리중`으로 바꾸고
화면을 옮기면 다시 `미처리`로 돌아온다. 보관도 마찬가지다.

## 원인

`src/api/endpoints/conversations.ts`에 **`getConversations` 하나뿐**이다.
`PATCH` 호출이 없다.

`src/components/ChatPane.tsx:298`이 로컬 상태만 바꾼다:

```tsx
onClick={() => dispatch({ type: 'setStatus', value: o })}
```

운영 DB 확인 결과 — 상태 변경 이벤트 0건, `PATCH` 요청 0건, `conversations.status`
그대로. 화면에서만 바뀐다.

## 서버 계약

B9가 만들어 검증까지 마쳤다. **`worker/routes/conversation-write.ts`와
`shared/wire/`의 계약을 직접 읽어라.** 내가 옮겨 적으면 어긋난다.

핵심만:

- `{ status?, archived?, label?, version }`을 받는다
- **`version`은 낙관적 잠금**이다. stale이면 **409 + `CONFLICT_VERSION`**과 함께
  현재 서버 값을 돌려준다
- 성공하면 `version`이 증가한다

## 반드시 지킬 것

### `version`을 반드시 실어라

목록 응답의 `ConversationListItem.version`을 쓴다. **빼먹으면 저장이 안 되거나
남의 수정을 덮어쓴다.** 두 사람이 같은 대화를 만지는 도구다.

### 409를 조용히 삼키지 마라

충돌하면 **사용자에게 알리고 현재 서버 값으로 화면을 맞춰라.**
그냥 되돌리기만 하면 "왜 안 바뀌지"가 된다 — 지금 사용자가 겪은 것이 정확히
그 경험이다.

### 낙관적 갱신은 실패 시 되돌려라

지금은 되돌리지도 않고 그냥 로컬에 남았다가 재조회에서 사라진다.
**요청 실패 시 이전 값으로 복원**해라.

### 보관은 상태와 다른 축이다

`archived`를 바꿀 때 `status`를 함께 바꾸지 마라. 보관된 `처리중`이
표현 가능해야 한다. 서버가 그렇게 설계돼 있다.

### 목록과 스레드가 같은 값을 봐야 한다

성공 응답으로 **목록 항목도 갱신**해라. 스레드 헤더만 바뀌고 목록 칩이
그대로면 또 어긋난다.

## 수용 기준

1. `npm run check` 통과
2. **상태를 바꾸고 다른 대화로 갔다가 돌아와도 유지된다.**
   실제 앱에서 재현해 확인해라 — 지금 결함의 직접 반례다
3. **새로고침해도 유지된다** (DB에 저장됐다는 뜻)
4. 보관 → 목록에서 사라지고 보관함에 나타난다. 새로고침해도 유지
5. 보관 해제 → 되돌아온다
6. **보관해도 `status`가 안 바뀐다**
7. `version`이 요청에 실린다
8. **409 → 사용자에게 보이고 화면이 서버 값으로 맞춰진다.**
   두 탭에서 각각 바꿔 실제로 재현해라
9. 요청 실패 → 화면이 이전 값으로 되돌아간다
10. 상태 변경 후 **목록 칩 숫자도 갱신**된다
11. `PATCH /api/conversations/:id`가 실제로 나가는 것을 네트워크에서 확인해라
