## 목표

**대화 스레드와 컴포저를 서버로 옮긴다.**

- 메시지 페이지 (B7) — `GET /api/conversations/:id/messages`
- 발송 (B17) — `POST /api/conversations/:id/messages`
- 첨부 인라인 렌더 + 다운로드 (X3) — `GET /api/attachments/:id`

## 지금 무엇이 틀렸는가 — 네 가지

### 1. 발신 말풍선이 *보고 있는 사람*의 이니셜을 렌더한다

어제 김세무가 보낸 답장을 박상담이 열면 **박상담이 보낸 것처럼 보인다.**
과거 이력의 발신자가 전부 거짓이다.

서버가 각 메시지에 `sender`를 준다. **인바운드는 `sender`가 `null`**이다 —
고객이 사무소 번호로 보낸 것이라 개인 식별이 안 된다. 그 차이를 화면에
드러내라.

이니셜은 `shared/text.ts`의 `initialOf()`로 **클라이언트가 파생**한다.
서버가 내려주지 않는다.

### 2. 컴포저 카운터가 `1,000자`다

실제 제약은 **글자 수가 아니라 바이트**이고 SMS 90 / LMS 2000이다.
그리고 **EUC-KR 기준이라 한글이 2바이트**다.

`shared/sms.ts`의 `smsByteLength`·`pickMessageType`을 **가져다 써라.**
서버(B17)가 같은 함수를 쓴다.

- **`new TextEncoder()`를 쓰지 마라** — UTF-8이라 한글이 3바이트로 세진다
- 직접 세지 마라. `grep -c TextEncoder`가 0이어야 한다
- 카운터는 `n / 90 byte` 형태로, SMS↔LMS 전환을 사용자가 보게 해라

**이모지는 서버가 400으로 거절한다.** 컴포저에서 같은 판단을 해서 보내기
전에 알려라 — `containsEmoji`가 있다. 서버 응답의 전용 오류 코드로도
분기할 수 있어야 한다.

### 3. "전송 완료"를 즉시 표시한다

**발송 200 응답은 *접수*일 뿐 도달이 아니다.** 실제 도달은 리포트로 온다.

`delivery_status`(`대기`·`접수`·`전송중`·`완료`·`실패`)를 그대로 반영해라.
`접수`를 "전송 완료"라고 쓰지 마라 — 상담원이 갔다고 믿는데 실패할 수 있다.

`실패`면 `error_text`를 볼 수 있게 해라.

### 4. 발신 채널 표기

**자유 텍스트는 항상 SMS/LMS로 나간다.** 알림톡은 사전 승인 템플릿만 되기
때문이다. `messages.channel`이 건별로 저장되니 **사실을 그대로 렌더**해라.

## 낙관적 갱신 — 중복 말풍선이 구조적으로 불가능하게

F1이 놓은 축대로 모든 발송에 `clientKey`(UUID)를 싣고 서버가 그대로 돌려준다.

리듀서는 **`clientKey` 먼저, 없으면 `id`로** 병합해 임시 말풍선을 교체해라.
id로만 병합하면 서버 응답이 오기 전 재시도했을 때 두 개가 남는다.

**같은 `clientKey`로 재시도해라.** 서버가 멱등이라 메시지는 하나다.
새 키를 만들면 고객이 문자를 두 번 받는다.

## 첨부

`GET /api/attachments/:id`가 인라인·다운로드 두 모드를 준다 (X3 소유).

- **이미지는 채팅창에 바로 보인다.** 다운로드 링크가 아니다
- **다운로드 버튼도 따로** 있어야 한다
- `download_status`가 `대기`면 "받는 중"을 표시해라. 없는 것과 구별된다
- R2 공개 URL을 만들지 마라. 고객 사업자등록증이 **링크만 알면 열리면 안 된다**

## 메시지 페이지 — 과거로 거슬러 올라간다

목록(F3)과 방향이 반대다. 최신이 아래고 위로 스크롤하며 과거를 불러온다.

서버가 **시간 오름차순**으로 준다. 다시 뒤집지 마라.
`nextCursor`로 이어 받되 **이미 받은 메시지를 다시 넣지 마라.**

과거를 불러올 때 **스크롤 위치가 튀지 않게** 해라.

## 반드시 지킬 것

`src/state/thread.ts`가 네 소유다. `src/state/inbox.ts`·`selectors.ts`를
건드리지 마라.

`thread.ts:68`의 `assignees: [...ME]` 자동 배정이 사라진다 — **서버(B17)가
첫 응신에 발신자를 자동 배정**한다. 클라이언트가 추측하지 마라.

## 수용 기준

1. `npm run check` 통과
2. **앱이 실제로 뜬다.** 스레드를 열고 메시지를 보내 확인해라
3. **발신 말풍선이 `sender.name` 기준이다.** 다른 사용자로 로그인해도
   과거 발신자가 그대로다 (결함 #3의 직접 반례)
4. 인바운드 말풍선에 발신자가 없고, 그게 화면에서 구별된다
5. **카운터가 `n / 90 byte`이고 한글이 2바이트로 센다**
6. `grep -c TextEncoder src/` = 0
7. 45자 한글에서 SMS→LMS 전환이 화면에 보인다
8. 이모지 입력 시 **보내기 전에** 알려준다
9. **배지가 `delivery_status`를 반영한다.** `접수`가 "전송 완료"로 표시되지 않는다
10. `실패` 메시지의 이유를 볼 수 있다
11. **낙관 말풍선 중복 0** — 응답 전 재시도해도 하나다
12. 재시도가 **같은 `clientKey`**를 쓴다
13. 이미지 첨부가 **인라인으로 보이고** 다운로드 버튼이 따로 있다
14. `download_status='대기'`면 "받는 중"이 보인다
15. 위로 스크롤해 과거를 받아도 **중복 0, 스크롤 위치 유지**
