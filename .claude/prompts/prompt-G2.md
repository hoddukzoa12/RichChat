## 목표

**대화를 업무폰별로 분리한다.** 같은 고객이 서로 다른 사무소 번호로 문자하면
**대화가 각각 생긴다.**

## 왜

사무소가 업무폰 9대를 쓰고 **각 폰의 담당자가 다르다.** 지금은
`ux_conv_customer UNIQUE(office_id, customer_id)`라 **고객 하나 = 대화 하나**여서,
1팀 폰과 2팀 폰에 온 문의가 한 스레드에 섞인다.

운영에서 실제로 났다 — 같은 고객의 LGU+ 12건과 게이트웨이 4건이 한 대화에 있다.

대화가 갈리면 **담당자·상태·메모·업무·안읽음이 전부 자동으로 갈린다.**
그리고 **답장을 어느 폰으로 보낼지가 대화만 보면 정해진다** — 발신 슬라이스가
여기에 올라탄다.

## 무엇을 바꾸나

### 스키마

`conversations`가 **어느 사무소 채널(업무폰)에 속하는지** 알아야 한다.
유니크 제약도 그만큼 넓어진다.

```
지금:   UNIQUE(office_id, customer_id)
바꿈:   UNIQUE(office_id, customer_id, <채널>)
```

`migrations/0009_*.sql`을 새로 만들어라. 기존 마이그레이션을 고치지 마라.

**`migrations/0005_add_deputy_administrator_role.sql`을 먼저 읽어라.**
거기서 `users` 재생성 때 겪은 함정이 그대로 적용된다:

- D1은 마이그레이션을 트랜잭션 안에서 돌려 `foreign_keys`를 끌 수 없다
- `DROP TABLE`이 지연 FK 카운터를 올리는데 rename으로는 안 내려간다
- `defer_foreign_keys = OFF`는 **검증이 아니라 카운터 해제**다
- 그래서 `pragma_foreign_key_check`를 세는 **가드**를 넣어 위반이 있으면
  전체가 롤백되게 했다

`conversations`를 참조하는 테이블이 여럿이다(`messages`·`notes`·`tasks`·
`conversation_assignees`·`conversation_reads`). **컬럼 추가만으로 되는지, 재생성이
필요한지 네가 판단하고 근거를 적어라.** 재생성이면 0005의 가드를 그대로 써라.

### 기존 데이터

지금 대화는 전부 LGU+ 대표번호로 온 것이다. **`is_default = 1` 채널에 묶어라.**

`office_channels`에 그 채널이 없으면 마이그레이션이 실패해야 한다 —
**조용히 NULL로 두지 마라.**

### 수신 경로

- **게이트웨이**: `deviceId`로 채널을 찾는다. 이미 그렇게 하고 있다
- **LGU+**: 채널 정보가 없다. `is_default` 채널을 쓴다

**대화를 찾을 때 채널까지 맞춰야 한다.** 지금은 고객만 보고 찾는다.

`worker/inbound-message.ts`가 공용 저장 지점이다. **양쪽이 같은 함수를 쓰므로
한 곳만 고치면 된다.**

### 응답에 채널을 실어라

목록과 상세 응답에 **어느 업무폰인지**가 있어야 한다. 없으면 화면에서 같은
고객이 두 줄인데 구별이 안 된다.

`office_channels.label`을 쓴다. 응답 모양은 네가 설계하되
**`shared/wire/`의 기존 타입 어법을 따라라.**

### 화면 — 최소한만

**목록 행과 스레드 상단에 라벨이 보이면 된다.** 그 이상 하지 마라.

지금 목록은 고객 이름만 보여준다. 같은 이름이 두 줄이면 **어느 폰인지 알 수
없어 쓸 수 없는 화면이 된다.** 그래서 이 슬라이스에 포함한다.

디자인은 `design/prototype.dc.html`과 `src/theme.ts`의 기존 값을 따라라.
새 색을 정하지 마라.

## 반드시 지킬 것

- **기존 불변식을 깨뜨리지 마라** — 멱등 수신, `inbound_count`, 정렬키 후퇴
  방지, `완료 → 미처리` 복귀. 기존 테스트가 그것을 지킨다
- **LGU+ 경로가 계속 동작해야 한다.** 병행 운영 중이다
- 비활성 채널로 온 수신을 **버리지 마라.** 어떻게 다룰지 판단하고 근거를 적어라
- `AGENTS.md`·`CLAUDE.md`·계획서를 고치지 마라. 고칠 것이 보이면 보고에 적어라

## 수용 기준

1. `npm run check` 통과
2. **같은 고객이 서로 다른 채널로 보내면 대화가 2개** 생긴다
3. **같은 고객이 같은 채널로 다시 보내면 대화가 1개**다 (기존 멱등성)
4. 기존 대화가 **기본 채널에 묶여** 마이그레이션된다. 행이 하나도 안 사라진다
5. 마이그레이션에 **FK 가드가 있고, 끊어진 참조가 있으면 롤백**된다
   (일부러 끊어서 실제로 확인해라)
6. LGU+ 수신이 여전히 동작한다 — 기존 MO 테스트가 **수정 없이** 통과
7. 게이트웨이 수신이 여전히 동작한다 — 기존 테스트 그대로
8. **목록과 스레드에 업무폰 라벨이 보인다.** 앱을 실제로 띄워 확인해라
9. 담당자·안읽음·상태가 **대화별로 독립**이다
10. `python3 .claude/scripts/dead-exports.py` · `positional-consts.py` 통과

커밋하고 `origin/hoddukzoa12/g2-conversation-split`에 푸시한 뒤 해시를 보고해라.
배포하지 마라.
