## 목표

**네이버웍스 OIDC 로그인.** 지금은 개발용 로그인밖에 없다.

```
GET  /api/auth/login      → 네이버웍스로 리다이렉트
GET  /api/auth/callback   → 세션 발급 후 앱으로 복귀
POST /api/auth/logout
```

`worker/http/session.ts`(B4)가 세션 **해석**을 이미 한다. 여기는 세션을
**발급**하는 쪽이다. 그 파일의 쿠키 이름·TTL·해시 방식을 읽고 **그대로 써라.**
새로 정의하면 발급과 검증이 어긋난다.

## 반드시 지킬 것

### 초대된 이메일만 들어온다

`users`에 `status='초대'`로 미리 있는 이메일만 로그인시킨다. **네이버웍스
인증에 성공했다는 것만으로 계정을 만들지 마라** — 같은 도메인 아무나 들어온다.

최초 로그인에 `works_sub`를 확정하고 `status`를 `활성`으로 바꾼다.
`status='비활성'`(퇴사자)은 인증에 성공해도 **거부**다.

미초대 → 403. 응답으로 **초대 여부를 알려주지 마라** — 계정 열거가 된다.

### state는 일회용이다

`oauth_states` 테이블이 있다. **`DELETE … RETURNING`으로 소비**해라.
`SELECT` 후 `DELETE`는 그 사이에 같은 state로 두 번 들어올 수 있다.

만료된 state도 거부한다. 만료 행은 정리해라.

### PKCE와 nonce

`code_verifier`는 `oauth_states`에 저장되고 콜백에서 꺼내 쓴다.
`nonce`는 **ID 토큰에서 꺼내 대조**해라. 저장만 하고 안 보면 없는 것과 같다.

### ID 토큰 검증 — 서명을 확인해라

`iss`·`aud`·`exp`·`nonce`를 검사하고, **JWKS로 서명을 검증**해라.
디코드만 하고 페이로드를 믿으면 누구나 토큰을 위조한다.

JWKS는 매 로그인마다 받지 말고 캐시하되, **키 롤오버 시 갱신**되게 해라.
검증 실패는 로그인 실패다 — 넘어가지 마라.

### 세션 고정

**로그인할 때마다 새 토큰을 발급**해라. 로그인 전 쿠키가 있어도 재사용하지 마라.
로그아웃은 DB 행을 지우고 쿠키를 만료시킨다 — **쿠키만 지우면 토큰이 계속 유효**하다.

### 열린 리다이렉트

`redirect_to`를 그대로 `Location`에 넣지 마라. **동일 출처 경로만** 허용하고,
`//evil.com`이나 `https://evil.com` 같은 값은 거부하거나 `/`로 대체해라.

### 시크릿

클라이언트 시크릿은 `wrangler.jsonc`의 `vars`가 아니라 **secret 바인딩**이다.
`vars`는 대시보드에 평문으로 보인다.

**이번 배치에서 `wrangler.jsonc`를 만지는 건 B18뿐이다.** 바인딩 이름을
`Env`에 선언만 하고, 설정 파일 변경이 꼭 필요하면 `ask`로 물어라.

### 오류 화면

콜백 실패를 JSON 500으로 끝내지 마라. 브라우저가 직접 방문하는 경로다.
로그인 화면으로 되돌리되 **내부 오류를 노출하지 마라.**

## 수용 기준

1. `npm run check` 통과
2. **같은 state로 콜백 2회 → 두 번째 400.** 실제로 두 번 호출해서 확인해라
3. 만료된 state → 400
4. 미초대 이메일 → 403, **`users` 행이 생기지 않는다**
5. `status='비활성'` 사용자 → 거부
6. 최초 로그인 → `works_sub` 저장, `status`가 `활성`으로
7. **`nonce` 불일치 → 거부** (대조를 실제로 하는지)
8. 서명이 틀린 ID 토큰 → 거부
9. `exp`가 지난 ID 토큰 → 거부
10. **로그인 2회 → 서로 다른 세션 토큰**
11. 로그아웃 후 그 쿠키로 API 호출 → 401 (**DB 행이 지워졌는지 확인**)
12. `redirect_to`가 `//evil.com`·`https://evil.com` → 외부로 안 나간다
13. 발급된 세션이 **B4의 `requireSession`으로 그대로 통과**한다
