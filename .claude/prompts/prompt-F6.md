## 목표

**설정 화면 둘을 서버로 옮긴다.**

- 내 설정 (B13) — `PATCH /api/me` · `PATCH /api/me/settings`
- 사무소 설정·팀 (B14) — `GET·PATCH /api/office/settings` · `GET /api/office/members` · `POST /api/office/invites`

## 반드시 지킬 것

### 연락처와 답장 서명 입력란을 **제거해라**

프로토타입 프로필에 둘 다 있는데 **스키마에 그 컬럼이 없다.** 의도적으로 뺐다:

- 업무폰이 따로 있고 발신은 사무소 발신번호로 나간다. 개인 연락처가 쓰이는
  곳이 없다
- 서명은 본문에 붙으면 `세무법인 리치 박상담 드림` 한 줄이 26바이트 —
  **SMS 90바이트의 29%를 먹는다.** 발신자는 웹 프로필로 구분되므로 붙일 이유가 없다

프로필은 **이름·직함·이메일**뿐이다. 이메일은 읽기 전용이다 (OIDC가 정한다).

### `isAdmin`은 서버에서 온다

`state/settings.ts`의 `isAdmin: true` 하드코딩을 **지워라.** F1이 Rail을
세션 기준으로 바꿨고, 여기가 나머지다.

**비관리자가 사무소 설정을 열면 403 화면**을 보여줘라. 메뉴를 숨기는 것만으로는
부족하다 — URL을 직접 치면 들어온다.

### 팀 목록

`GET /api/office/members`는 **비관리자도 볼 수 있다** — 담당자 배정 UI가 이
목록을 쓴다.

다만 서버가 비관리자에게는 민감한 필드(초대 상태 등)를 주지 않는다.
**없는 필드를 클라이언트가 채워 넣지 마라.**

### 초대

이메일 검증을 서버에 맡겨라. `'@x.com'`·`'a@'`·공백만 같은 값에 **크래시하지
않고 서버 400을 그대로 보여주면 된다.**

**클라이언트에서 `split('@')`으로 이름을 만들지 마라.** 그게 지금 결함(#13)이다.

이미 초대된 이메일을 다시 초대해도 **행이 두 개 되지 않는다** — 서버가 멱등이다.
화면에서 중복 항목을 만들지 마라.

### 보존 기간

`retention_years`에 서버가 범위 검증을 건다. 0·음수·비정상 값은 400이다.
입력에 최소한의 안내를 두되 **클라이언트 검증을 신뢰하지 마라** — 서버 응답을
그대로 반영해라.

### 낙관적 갱신

변경 요청에 `clientKey`를 싣는다 (F1 축). 실패하면 **되돌려라.**
저장된 것처럼 보이는데 아닌 상태를 만들지 마라.

## 수용 기준

1. `npm run check` 통과
2. **앱이 실제로 뜬다.** 두 설정 화면을 열어 확인해라
3. **연락처·답장 서명 입력란이 없다.** `grep`으로 확인해라
4. `state/settings.ts`의 `isAdmin` 하드코딩이 **삭제된다**
5. **비관리자가 사무소 설정에 접근 → 403 화면.** 메뉴 숨김만으로 끝내지 않는다
6. 관리자 저장 → 반영되고 다시 열어도 유지된다
7. 팀 목록이 `/api/office/members`에서 온다. 목 데이터 0건
8. 비관리자도 팀 목록을 본다
9. **`'@x.com'` 초대 → 크래시 없이 오류 메시지** (결함 #13)
10. 같은 이메일 재초대 → 화면에 항목이 하나
11. 프로필 이름 변경 후 다른 화면(레일·메모)에 반영된다
12. 이메일 입력이 읽기 전용이다
13. 저장 실패 시 화면이 되돌아온다
