## 목표

**내 프로필과 알림 설정.**

```
PATCH /api/me            { name?, title? }
PATCH /api/me/settings   { notifyNewChat?, notifyMineOnly?, notifySound? }
```

`GET /api/me`는 B4가 이미 만들었다. **그 파일을 고치지 마라** — 여기는 쓰기다.

## 반드시 지킬 것

### 이메일과 역할은 못 바꾼다

`PATCH /api/me`로 `email`이나 `role`을 바꿀 수 있으면 **권한 상승**이다.
자기를 관리자로 만들 수 있게 된다.

본문에 그 필드가 와도 **조용히 무시하거나 400**으로 거부해라.
`UPDATE` 문의 `SET` 절에 아예 넣지 마라.

`status`·`works_sub`·`office_id`도 마찬가지다.

### 내 것만 바꾼다

`WHERE id = ?`에 **세션의 `userId`**를 넣는다. 경로나 본문에서 대상 id를
받지 마라.

### 연락처와 답장 서명은 없다

프로토타입 설정 화면에 연락처·답장 서명 입력란이 있는데 **스키마에 그 컬럼이
없다.** 의도적으로 뺐다:

- 업무폰이 따로 있고 발신은 사무소 발신번호로 나간다
- 서명은 본문에 붙으면 `세무법인 리치 박상담 드림` 한 줄이 26바이트 —
  SMS 90바이트의 29%를 먹는다. 발신자는 웹 프로필로 구분된다

**그 필드를 되살리지 마라.** 화면에서 지우는 건 F6이 한다.

### 설정 행이 없을 수도 있다

`user_settings`는 사용자 생성 시 만들어지지 않을 수 있다. **upsert로 처리해라** —
없으면 기본값으로 만들고 갱신한다. 400을 던지지 마라.

`ON CONFLICT(user_id) DO UPDATE`를 쓴다.

### 불리언은 0/1이다

스키마가 `CHECK (... IN (0,1))`인 정수다. `true`/`"true"`/`1`을 받아
정규화하되, **아무거나 truthy로 통과시키지 마라.** `"false"` 문자열이
참이 되는 사고가 난다.

### 부분 갱신

보내지 않은 필드는 **건드리지 않는다.** 이름만 고치려다 직함이 지워지면 안 된다.

## 수용 기준

1. `npm run check` 통과
2. 쿠키 없이 호출 → 401
3. **본문에 `role: '관리자'`를 넣어도 역할이 안 바뀐다.** 실제로 시도하고
   DB를 읽어 확인해라
4. `email`·`status`·`office_id`·`works_sub` 변경 시도 → 전부 무시/거부
5. 이름 변경 후 `GET /api/me`에 반영된다
6. **이름만 PATCH → 직함 유지**
7. 설정 행이 없는 사용자가 PATCH → 행이 생기고 반영된다
8. 두 번째 PATCH → 행이 2개가 되지 않는다
9. `"false"` 문자열이 참으로 해석되지 않는다
10. 본문에 다른 사용자 id를 넣어도 세션 사용자만 바뀐다
11. **연락처·서명 필드가 요청·응답·스키마 어디에도 없다**
12. 변경 1건당 이벤트 1건
