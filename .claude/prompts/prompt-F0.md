## 목표

`src/state/inbox.ts`를 쪼갠다. **순수 리팩터다 — 동작이 바뀌면 실패다.**

지금 한 파일에 상태 모양·초기값·60개 가까운 액션·리듀서가 전부 들어 있다.
앞으로 목록·스레드·고객카드·설정 슬라이스가 각각 이 파일을 고쳐야 하는데,
그러면 서로 충돌한다. 미리 갈라두면 각 슬라이스가 자기 조각만 만진다.

## 원칙

**액션 이름을 바꾸지 마라.** 컴포넌트가 그 이름으로 dispatch하고,
서버 연동 슬라이스에서 이 이름들이 API 계약으로 승격된다. 이름을 바꾸면
그 대응이 끊긴다.

**동작을 고치지 마라.** 이 파일에 알려진 버그가 몇 개 있지만 여기서 고치지
않는다. 리팩터와 수정을 섞으면 무엇이 회귀인지 알 수 없다. 발견하면
보고만 해라.

**파일을 쪼개는 것 자체가 목적이 아니다** (`AGENTS.md` §3). 관심사가 다른
덩어리를 가르는 것이지, 줄 수를 맞추려고 자르는 게 아니다.

## 가르는 축

상태와 액션을 관심사별로 묶어라. 대략 이런 축이 보인다:

- **화면 상태** — 어느 페이지·탭·모바일 뷰, 열린 드롭다운, 카드 펼침
- **목록** — 검색어, 상태·담당·채널 필터, 보관함 보기
- **스레드** — 선택된 대화, 입력 중인 메시지, 전송
- **고객 카드** — 정보 편집, 업무 CRUD, 메모 CRUD
- **설정** — 프로필, 알림, AI 토글, 사무소 정책, 직원 초대

정확한 분할은 네가 판단해라. 위는 참고다. **어디에도 안 맞는 것이 있으면
억지로 밀어넣지 말고 보고해라.**

`src/state/inbox.ts`는 조각들을 합치는 얇은 파일로 남긴다. 상태 타입과
초기값이 거기 있어야 할지, 각 조각으로 갈지도 네가 정해라.

## 반드시 지킬 것

- **`shared/`의 타입을 쓴다.** `Status`·`Channel` 같은 도메인 유니온은
  `shared/domain.ts`에 있고 `src/types.ts`가 재수출한다. 새로 정의하지 마라
- 컴포넌트를 수정하지 마라. `useInbox()`가 주는 것이 그대로여야 한다
- `src/state/selectors.ts`를 건드리지 마라 — 다른 슬라이스 소유다

## 동작 불변을 어떻게 증명하나

이게 이 슬라이스의 핵심이다. "돌려봤더니 되더라"로는 부족하다.

**액션 시퀀스를 넣고 최종 상태를 비교하는 테스트**를 써라. 리팩터 전후가
같은 결과를 내는지 고정하는 것이다. 대화 선택 → 메시지 전송 → 상태 변경 →
담당자 배정 → 메모 추가 → 업무 수정처럼, 실제로 쓰이는 흐름을 덮어라.

테스트 이름은 영문으로 쓴다 (`AGENTS.md` 언어 규칙).

**브라우저에서도 확인해라.** `npm run dev`로 띄워 목록·대화·고객카드·설정을
눌러보고 이전과 같은지 봐라. 콘솔 오류가 있으면 보고해라.

## 수용 기준

1. `npm run check` 통과
2. **액션 이름이 하나도 사라지거나 바뀌지 않았다** — 리팩터 전후의 액션
   이름 집합을 비교해서 증명해라
3. 액션 시퀀스 테스트가 존재하고 통과한다
4. `src/components/` 무변경 (`git diff --name-only`로 증명)
5. `src/state/selectors.ts` 무변경
6. 브라우저에서 목록·대화·고객카드·설정이 이전과 동일하게 동작하고
   콘솔 오류 0건
7. `src/state/inbox.ts`가 조각들을 합치는 역할로 줄었다

## 발견해도 고치지 말 것

이 파일에는 알려진 문제가 있다. **전부 나중 슬라이스가 고친다.**

- 배열 인덱스로 메모·업무를 지우고 수정하는 것
- `ME` 상수에 의존하는 필터와 권한 검사
- 시각을 포맷된 문자열로 저장하는 것
- `sendInvite`가 `@`로 시작하는 이메일에 크래시하는 것

발견하면 **보고만 해라.** 여기서 고치면 리팩터와 수정이 섞여 회귀 판별이 안 된다.
