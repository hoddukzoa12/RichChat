## 목표

**읽음 커서 전진.** `POST /api/conversations/:id/read`

작은 슬라이스다. 하지만 안읽음 배지의 정확성이 여기에 달려 있다.

## 지금 무엇이 틀렸는가

`unread`가 **전역 정수 하나**다. A가 대화를 열면 아직 안 본 B의 배지도 사라진다.
직원 여러 명이 인박스를 공유하는 도구에서 이건 놓친 문의로 이어진다.

## 반드시 지킬 것

### 사용자별이다

`conversation_reads`가 `(conversation_id, user_id)` 복합 PK다.
`user_id`는 **세션에서** 온다.

### 후퇴하지 않는다

커서는 **단조 증가**한다. 오래된 값이 도착해도 되돌아가면 안 된다.

```sql
INSERT INTO conversation_reads (conversation_id, user_id, read_inbound_count, updated_at)
VALUES (?, ?, ?, ?)
ON CONFLICT(conversation_id, user_id)
DO UPDATE SET read_inbound_count = MAX(excluded.read_inbound_count, read_inbound_count),
              updated_at = ?
```

**한 문장으로 표현해라.** 읽고 나서 비교하고 쓰면 그 사이에 다른 탭이
더 큰 값을 쓸 수 있다.

왜 중요한가 — 탭 두 개를 열어두면 오래된 탭이 뒤늦게 낡은 커서를 보낸다.
후퇴하면 이미 읽은 메시지가 안읽음으로 되살아난다.

### 넘겨받은 값을 그대로 믿지 마라

`inbound_count`보다 큰 값이 오면 잘라라. 크게 보내서 미래의 메시지까지 읽음
처리하는 걸 막아야 한다.

음수나 정수가 아닌 값은 400이다.

### 이벤트

읽음도 이벤트를 낸다 — 다른 탭의 배지가 갱신돼야 한다.

**커서가 실제로 전진했을 때만** 낸다. `MAX()`가 기존 값을 유지했다면 변경이
없었으므로 이벤트도 없다. 안 그러면 탭을 열어둔 것만으로 이벤트가 쏟아진다.

`worker/db/events.ts`의 조건부 발행을 쓴다 — **먼저 그 파일을 읽어 현재
시그니처를 확인해라.** 방금 확장됐다.

### 남의 커서를 못 옮긴다

`user_id`를 본문이나 쿼리에서 받지 마라. 세션 것만 쓴다.

## 수용 기준

1. `npm run check` 통과
2. 쿠키 없이 호출 → 401
3. **오래된 값으로 호출 → 커서가 후퇴하지 않는다.** 큰 값 후 작은 값 순서로
   실제 호출해서 확인해라
4. **사용자 A가 읽어도 B의 커서는 그대로다**
5. 처음 호출 → 행이 생긴다. 두 번째 → 갱신된다 (행 2개가 되지 않는다)
6. `inbound_count`보다 큰 값 → 잘린다
7. 음수·정수 아님 → 400
8. **커서가 전진했을 때만 이벤트 1건. 같은 값 재호출 → 이벤트 0건**
9. 본문에 다른 `userId`를 넣어도 세션 사용자의 커서만 움직인다
10. 없는 대화 id → 404
