## 목표

**사무소 직원 관리를 제대로 만든다.** 초대·수정·비활성화.

S1이 `부관리자` 역할과 권한 판정 함수를 이미 넣었다. **그것을 가져다 써라.**
권한 비교를 여기서 새로 만들지 마라.

## 지금 무엇이 틀렸는가 — 셋

### 1. 초대할 때 이름 자리에 이메일이 들어간다

`worker/routes/office.ts`의 INSERT를 봐라:

```
invite.email,   → email
invite.email,   → name      ← 이름 자리에 이메일
invite.role,    → title     ← 직함 자리에 역할 문자열
invite.role,    → role
```

화면에 사람 이름 대신 이메일이 뜬다. 직함에는 `상담 담당` 같은 역할이 박힌다.

**초대 요청에 이름을 받아라.** 직함도 함께 받되 선택으로 둘지는 네가 판단해라.

### 2. 본인이 자기 직함을 바꿀 수 있다

`PATCH /api/me`가 `title`을 받는다. **스스로 "대표세무사"라고 적을 수 있다는 뜻**이라
사무소 도구에서 맞지 않는다.

`me.ts`에서 **`title`을 수정 대상에서 빼라.** `name`은 본인이 고칠 수 있게 둔다.
직함은 관리자·부관리자가 정한다.

**`/api/me` 응답에서 `title`을 빼지는 마라** — 화면이 표시에 쓴다. 쓰기만 막는다.

### 3. 초대 후 손댈 방법이 없다

역할을 잘못 지정했거나 퇴사해도 바꿀 수 없다.

## 만들 것

**직원 수정**과 **비활성화**. 경로·모양은 기존 사무소 API와 일관되게 네가 정해라.

- 수정 대상: **직함·역할**. 이름도 관리자가 고칠 수 있게 할지는 네가 판단해라
- **"삭제"는 행 삭제가 아니라 `status='비활성'`이다.**
  `users`를 참조하는 FK가 11개다 — 메시지 발신자·메모 작성자·업무 생성자·
  담당자 배정·이벤트 액터. 행을 지우면 과거 이력이 깨진다.
  비활성이면 로그인은 막히고(B4가 이미 `활성`만 통과시킨다) 이력은 남는다
- 비활성 해제도 있어야 한다. 실수로 눌렀을 때 되돌릴 수 있어야 한다

## 권한 — S1의 함수로 판정해라

| 동작 | 관리자 | 부관리자 | 세무사·상담 담당 |
|---|---|---|---|
| 팀 목록 조회 | ✓ | ✓ | ✓ |
| 초대·직함 수정·역할 수정·비활성화 | ✓ | ✓ | ✗ |
| **관리자를 대상으로 위 동작** | ✓ | **✗** | ✗ |
| **관리자 역할로 임명·초대** | ✓ | **✗** | ✗ |
| 사무소 설정 | ✓ | ✗ | ✗ |

**초대 가능한 역할이 넷 전부로 늘어난다.** 지금 `InviteRole`이 관리자를
제외하고 있는데, 관리자는 관리자를 초대할 수 있어야 한다. 부관리자는 못 한다.

### 반드시 SQL에서 강제해라

응용 코드의 `if`로만 막지 마라. **403은 `meta.changes === 0`으로 판정**한다.
`_api-conventions.md`의 예시를 따라라.

## 잠기지 않게 하는 가드

**마지막 관리자를 비활성화하거나 강등할 수 없다.** 그러면 사무소에 아무도
못 들어온다 — 개발 로그인은 운영에서 닫혀 있고 복구는 DB 직접 수정뿐이다.

**자기 자신을 비활성화할 수 없다.** 실수로 자기를 잠그는 것을 막는다.
역할 강등도 같은 이유로 막을지는 네가 판단하되 근거를 적어라.

## 반드시 지킬 것

이미 `활성`인 사람을 다시 초대해도 **`초대`로 되돌리지 마라.** 멀쩡히 일하는
직원이 로그인을 잃는다. 기존 동작이 그러하니 깨뜨리지 마라.

`works_sub`를 건드리지 마라. 최초 로그인이 확정한다.

이메일 정규화는 `shared/email.ts`를 써라. 직접 `trim()` 하지 마라.

변경 1건당 이벤트 1건, **0행 변경 시 이벤트 0건.** 조건부 발행 가드를 써라.

## 수용 기준

1. `npm run check` 통과
2. **초대에 이름을 넣으면 그 이름으로 저장된다.** 이메일이 이름 자리에 안 들어간다
3. 초대 시 직함이 역할 문자열로 채워지지 않는다
4. **네 역할 전부로 초대할 수 있다** (관리자 포함)
5. **부관리자가 관리자 역할로 초대 → 403, 행 생성 안 됨**
6. **부관리자가 관리자를 수정·비활성화 → 403, 행 불변**
7. 부관리자가 세무사·상담 담당·부관리자를 수정·비활성화 → 성공
8. 세무사·상담 담당이 초대·수정·비활성화 → 403, 행 불변
9. **`PATCH /api/me`로 `title`을 바꿀 수 없다.** DB를 직접 읽어 확인해라
10. `/api/me` 응답에는 `title`이 여전히 있다
11. **마지막 관리자 비활성화·강등 → 거부.** 실제로 시도해라
12. 자기 자신 비활성화 → 거부
13. 비활성 → 그 계정으로 로그인 불가. 해제하면 다시 가능
14. **비활성해도 과거 메시지·메모의 작성자 정보가 남는다**
15. 이미 `활성`인 사용자 재초대 → `활성` 유지
16. 변경 1건당 이벤트 1건, 403일 때 0건
