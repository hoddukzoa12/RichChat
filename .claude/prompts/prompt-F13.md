## LGU+ 발송 제약 — 수신과 완전히 다르다

내가 공식 문서에서 확인한 값이다.

```
POST https://mnt-api.msghub.uplus.co.kr/file/v1/mms   multipart/form-data
허용 형식: JPG, JPEG, GIF (GIF는 첫 프레임만 사용)
최대 크기: 300KB
최대 크기(픽셀): 1500 × 1440
응답: data.fileId
```

**PNG가 허용 목록에 없다.** 수신(MO)은 형식·크기 제한이 없지만 발송은 이렇다.

## 무엇을 만드나

### 아무 이미지나 고르게 하고, 규격에 맞춰 바꿔라

**PNG를 거부하지 마라.** 스크린샷이 PNG라 거부하면 실무에서 자주 막힌다.
브라우저에서 **JPEG로 재인코딩**해 올리면 된다.

세 제약을 화면에서 해결해라:

| 제약 | 처리 |
|---|---|
| JPG·JPEG·GIF만 | JPEG로 변환 |
| 300KB | 품질을 낮춰 맞춘다 |
| 1500×1440px | 축소한다 |

**최대 3장**이다.

**새 라이브러리를 넣지 마라.** 캔버스로 된다.

### 함정 — EXIF 방향

아이폰·안드로이드 사진에는 **회전 정보(EXIF orientation)**가 들어 있다.
캔버스에 그대로 그리면 **사진이 눕거나 뒤집힌다.**

브라우저마다 동작이 다르니 **실제로 회전된 사진으로 확인해라.**
결과를 보고에 적어라.

HEIC(아이폰 기본 형식)를 브라우저가 디코드하는지도 확인하고,
**안 되면 그 사실을 사용자에게 알려라.** 조용히 실패하지 마라.

### 고른 뒤 화면

- **미리보기**가 보인다
- **한 장씩 뺄 수 있다**
- 변환 중이면 그것이 보인다 (큰 사진은 시간이 걸린다)
- **못 쓰는 파일은 이유를 말한다.** "실패"가 아니라 무엇이 문제인지

### 바이트 카운터

지금 `n / 90 byte · SMS`처럼 뜬다. **이미지가 붙으면 MMS가 된다.**
카운터가 그걸 반영해야 하는지 판단하고, **판단과 근거를 보고에 적어라.**

`shared/sms.ts`의 `pickMessageType`은 `SMS | LMS | TOO_LONG`만 돌려준다.
**그 파일을 고치지 마라** — 이 슬라이스 소유가 아니다. 화면에서 다뤄라.

### 본문 없이 사진만 보낼 수 있는가

수신 쪽에서는 본문이 `null`인 사진 전용 MMS가 실제로 온다.
**보낼 때도 허용할지 판단하고 근거를 적어라.**

## 수용 기준

**실제로 앱을 띄워서 확인해라.**

1. `npm run check` 통과
2. **버튼을 누르면 파일 선택창이 열린다**
3. **PNG를 고르면 JPEG로 변환돼 미리보기가 뜬다**
4. 300KB 넘는 사진이 **300KB 이하로 줄어든다** — 실제 바이트를 확인해라
5. 1500×1440을 넘는 사진이 **그 안으로 줄어든다**
6. **회전 정보가 있는 사진이 똑바로 보인다**
7. 3장까지 되고 4장째는 거부되며 **이유가 보인다**
8. 한 장씩 뺄 수 있다
9. 이미지가 아닌 파일(PDF 등)은 **이유를 말하고 거부한다**
10. 전송하면 서버 문구가 뜨고 **고른 사진이 남아 있다**
11. 새 npm 의존이 없다 — `package.json` 변경 0
12. 모바일 폭에서 동작한다
