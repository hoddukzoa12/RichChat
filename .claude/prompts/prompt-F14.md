## 목표

**고른 이미지를 실제로 올려서 함께 발송한다.** 마지막 배선이다.

F13이 컴포저에서 이미지를 고르고 JPEG로 변환하는 것까지 만들었다.
B22가 서버를 만들었다. **둘을 잇는 것이 없다.**

```
고르기(F13) ✅ → 업로드 ❌ → 발송(B22) ✅
```

## 서버 계약 — 이미 있다. 직접 읽어라

**추측하지 마라.** 아래는 길잡이이고 정본은 코드다.

### 업로드

```
POST /api/conversations/:id/attachments
multipart/form-data
  files = 이미지 1~3장 (같은 이름으로 여러 개)
→ 201 { attachments: MessageAttachment[] }
```

`worker/routes/message-attachments-upload.ts`를 읽어라.
응답 타입은 `UploadMessageAttachmentsResponse`다.

### 발송

`shared/wire/message-send.ts`

```ts
attachments?: SendMessageAttachment[]   // { id }
```

업로드가 돌려준 **첨부 id**를 발송에 싣는다.

### 제약

`src/lib/composeImage.ts`의 `COMPOSE_IMAGE_LIMITS`가 정본이고,
그것은 `shared/attachments.ts`의 `OUTBOUND_IMAGE_LIMITS`를 확장한 것이다.
**숫자를 새로 쓰지 마라.**

## 판단할 것 — 근거를 보고에 적어라

### 언제 올리는가

**고를 때** 올리면 발송이 빠르고 오류를 일찍 보여준다. 대신 사용자가 이미지를
빼거나 대화를 떠나면 **서버와 LGU+에 고아 파일이 남는다.**

**보낼 때** 올리면 고아가 안 생기지만 전송 버튼이 느려진다.

**정하고 근거를 적어라.** 고아가 생기는 쪽을 고른다면 그것을 어떻게 다룰지도
적어라 — "나중에 정리한다"는 계획이 없으면 그냥 쌓인다.

### 발송이 실패하면

**이미 올린 것을 다시 올리지 마라.** 첨부 id는 유효한 채로 남는다.
상담원이 다시 전송을 누르면 **같은 id로 재발송**되어야 한다.

이 저장소는 `client_key`로 발송 멱등성을 얻는다. **재시도에서 그 키가
유지되는지 확인해라** — 새로 만들면 메시지가 두 건 생긴다.

## 반드시 지킬 것

- **업로드가 실패하면 발송하지 마라.** 이미지 없는 문자가 나가면 고객이
  "사진이요?"라고 되묻는다
- **실패해도 고른 이미지를 날리지 마라.** 다시 고르게 만들지 마라
- **진행 중임을 보여라.** 큰 사진 3장은 시간이 걸린다. 그동안 버튼이 죽은 것처럼
  보이면 안 된다
- **낙관적 말풍선에 이미지가 보여야 한다.** 지금 텍스트는 즉시 보인다.
  이미지만 나중에 나타나면 어긋나 보인다
- `contentUrl`·R2 주소를 화면에 쓰지 마라. 첨부는 `/api/attachments/:id`로만 본다

## 지금은 `22002`로 실패한다 — 정상이다

발신번호가 LGU+에 등록되기 전이라 **발송은 반드시 실패한다.**
`22002 미등록 발신번호`가 나온다.

**그 전에 업로드는 성공해야 한다.** 그게 이 슬라이스가 증명할 수 있는 전부이고,
충분하다. 발송은 발신번호가 등록되면 내가 확인한다.

**업로드가 성공했는데 발송이 실패한 상태를 화면이 납득 가능하게 다뤄라.**

## 수용 기준

**실제로 앱을 띄워서 확인해라.**

1. `npm run check` 통과
2. **이미지를 붙여 전송하면 `POST .../attachments`가 실제로 나간다**
   (네트워크에서 확인)
3. **업로드 응답의 id가 발송 요청에 실린다**
4. 업로드 실패 시 **발송 요청이 나가지 않는다**
5. 실패 후에도 **고른 이미지가 남아 있다**
6. **재시도해도 같은 이미지를 다시 올리지 않는다**
7. 재시도에서 `client_key`가 유지되어 **메시지가 두 건 생기지 않는다**
8. 업로드 중임이 화면에 보인다
9. 낙관적 말풍선에 이미지가 보인다
10. `grep -rn "cloudfront\|r2_key" src/`가 0건
11. 새 npm 의존이 없다
12. 모바일 폭에서 동작한다

## 참고

`22002`로 실패하면 이 슬라이스는 성공**이다.
