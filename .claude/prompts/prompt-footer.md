## 공통 규칙 (모든 슬라이스에 적용)

### 건드리지 말 것

- `AGENTS.md`, `CLAUDE.md` — 조정자만 쓴다
- `design/` — 디자인 원본, 이식 근거로 보존
- `.claude/`, `.mcp.json` — 에이전트 설정
- **다른 슬라이스가 소유한 파일.** 위 "만들 것"에 없는 파일을 고쳐야 할 것
  같으면 **고치지 말고 `ask`로 물어라.** 20개 넘는 슬라이스가 병렬로 도는 중이라
  공용 파일을 건드리면 병합에서 충돌한다

특히 이 셋은 각각 한 슬라이스만 소유한다. 네 것이 아니면 손대지 마라:
`worker/index.ts` · `shared/wire/index.ts` · `wrangler.jsonc`

### 막히면 물어라

지시가 모순되거나, 설계가 이상해 보이거나, 소유 밖 파일을 고쳐야 할 것 같으면
**추측해서 진행하지 말고 `ask`로 조정자에게 물어라.** 답이 올 때까지 기다린다.

조용히 우회하는 것보다 멈추는 게 낫다. 잘못된 가정 위에 쌓으면 나중에 전부
다시 해야 한다. 실제로 이 프로젝트에서 조정자 프롬프트에 모순이 있었고,
물어봐서 잡았다.

### 완료 처리

1. `npm run check` 통과 확인 (타입체크 + 실제 D1/workerd 테스트)
2. 변경분을 **커밋하고 자기 브랜치에 푸시**한다
   커밋 메시지는 한국어로, **무엇을 왜 했는지** 쓴다. 무엇만 쓰지 마라
3. `worker_done`으로 보고한다:
   - 수용 기준 **각각**을 어떤 명령으로 확인했는지, 실제 출력과 함께
   - 커밋 해시
   - 통과하지 못한 항목이 있으면 **숨기지 말고 그대로** 적는다

기준을 충족하지 못한 채 "완료"로 보고하지 마라. 못 한 것을 적은 보고가
못 한 것을 숨긴 보고보다 훨씬 쓸모 있다. 조정자가 직접 재검증하므로
숨겨도 드러난다.
