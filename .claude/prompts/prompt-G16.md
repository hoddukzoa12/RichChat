# G16 — 세무정보 편집 칸 레이아웃 붕괴

`AGENTS.md`를 먼저 읽고 그 원칙을 따라라.

## 재현된 결함이다

고객 카드 편집 모드에서 세무정보 각 행이 무너진다. **키 입력칸이 행 전체
폭을 먹고, 값 입력칸과 삭제 버튼이 오른쪽 가장자리에 0폭으로 짜부라진다.**
값(`123-45-67890` 등)이 사라진 것처럼 보인다. 보기 모드는 정상이다.

원인은 `src/components/card/InfoTabView.tsx:10`:

```ts
const inputClass =
  'w-full text-[13.5px] ...'
```

키 입력칸이 `` `${inputClass} w-[92px] flex-none ...` ``로 합성되는데,
**`w-full`과 `w-[92px]`가 둘 다 적용되면 이긴 쪽은 className 나열 순서가
아니라 생성된 CSS의 순서다.** 이 빌드에서는 `w-full`이 이겨서 키 칸이
전체 폭이 된다. Tailwind에서 같은 속성의 유틸리티를 겹쳐 쓰는 것 자체가
결함이다 — 나열 순서로 덮어써진다는 가정은 성립하지 않는다.

## 무엇을 하는가

충돌을 제거해라. 방법은 네가 정하되(예: `inputClass`에서 `w-full`을 빼고
필요한 곳에만 명시), **같은 속성의 유틸리티가 한 요소에 두 번 실리는 곳이
남으면 안 된다.** `inputClass`를 쓰는 다른 자리(이름·상호·직함·업무·메모
입력)가 깨지지 않는지 전부 확인해라.

원본 디자인은 `design/prototype.dc.html`이다. 편집 모드 행 구성(키 92px +
값 flex + 삭제)이 원본과 맞는지 대조해라.

## 수용 기준

1. `npm run check` 통과
2. **실제 렌더에서** 편집 모드의 각 행이 키(고정 폭)·값(나머지 폭)·삭제로
   보이고, 기존 값이 편집 가능한 상태로 나타난다. 로컬에서 브라우저나
   컴포넌트 테스트의 DOM으로 확인해라 — 클래스 문자열 검사로 통과 판정하지
   마라. 이 결함 자체가 클래스 문자열은 옳아 보이는데 렌더가 깨진 경우다
3. `inputClass`를 쓰는 다른 입력칸들의 렌더가 그대로다
4. 회귀 테스트: 키 입력칸의 계산된 폭이 전체 폭이 아님을 잠가라
5. `python3 .claude/scripts/dead-exports.py` · `positional-consts.py` ·
   `unwired-routes.py` 통과
6. 커밋하고 `origin/hoddukzoa12/g16-fields-edit-layout`에 푸시한 뒤 해시를
   보고해라. **배포하지 마라.**
