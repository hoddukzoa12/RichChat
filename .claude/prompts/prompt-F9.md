## 목표

**서버에 있는데 화면이 부르지 않는 두 경로를 연결한다.**

1. **로그아웃** — `POST /api/auth/logout` (B5)
2. **읽음 커서** — `POST /api/conversations/:id/read` (B8)

둘 다 백엔드가 완성돼 있고 테스트도 통과한다. **프론트가 호출하지 않을 뿐이다.**

## 지금 무엇이 틀렸는가

### 로그아웃 버튼이 장식이다

`src/components/MySettings.tsx:255-260`:

```tsx
<button type="button" className="...">
  로그아웃
</button>
```

**`onClick`이 없다.** `src/api/` 어디에도 로그아웃 클라이언트가 없다.
사용자가 눌러도 아무 일이 안 일어난다.

세션이 7일짜리라 **공용 PC에서 로그아웃이 안 되면 다음 사람이 그대로 들어간다.**

### 안읽음 배지가 영원히 안 지워진다

`conversation_reads` 테이블의 행이 **0개**다. 아무도 읽음 처리를 한 적이 없다.

대화를 열어도 안읽음 숫자가 그대로 남는다. 직원 여러 명이 공유하는
인박스에서 이건 "누가 봤는지 모르는" 상태가 계속된다는 뜻이다 —
이 도구의 핵심 기능 하나가 죽어 있다.

## 무엇을 하나

### 로그아웃

`src/api/endpoints/` 아래 자기 자리에 클라이언트를 만들고 버튼에 연결해라.

**성공 후 반드시 클라이언트 상태를 비워라.** 서버 세션만 지우고 화면에
데이터가 남아 있으면 다음 사람이 그것을 본다. 로그인 화면으로 돌아가야 한다.

**폴링과 소켓이 멈춰야 한다.** F7이 `useRealtime`에 정리 경로를 만들어뒀다 —
그것이 실제로 도는지 확인해라. 로그아웃 후에도 `/api/events` 요청이 계속
나가면 401이 쌓인다.

실패하면 **화면을 되돌리고 알려라.** 로그아웃된 것처럼 보이는데 세션이
살아 있는 게 가장 나쁘다.

### 읽음 커서

`worker/routes/reads.ts`와 `shared/wire/`의 계약을 **먼저 읽어라.**
요청 모양을 추측하지 마라.

**언제 보내는가** — 사용자가 대화를 열어 메시지를 실제로 본 시점이다.
목록에서 스치듯 지나갈 때마다 보내지 마라.

**서버가 단조 증가를 보장한다** (`MAX()` upsert). 낡은 값을 보내도 후퇴하지
않으니 클라이언트가 그 판단을 다시 하지 마라.

**낙관적으로 배지를 지우되 실패하면 되돌려라.** 서버가 거부했는데 화면에서
사라지면 안 본 문의를 놓친다.

**대화를 열 때마다 무조건 보내지 마라.** 이미 0이면 요청이 낭비다.

## 반드시 지킬 것

`src/api/endpoints/index.ts` 배럴에 새 모듈을 추가해야 하면 **그 줄만** 더해라.

기존 화면 동작을 바꾸지 마라. 이 슬라이스는 **빠진 호출을 잇는 것**이지
UI를 다시 만드는 게 아니다.

## 수용 기준

1. `npm run check` 통과
2. **앱이 실제로 뜬다**
3. **로그아웃을 누르면 로그인 화면으로 돌아간다**
4. **로그아웃 후 `POST /api/auth/logout`이 실제로 나간다** (네트워크에서 확인)
5. **로그아웃 후 `/api/events` 폴링이 멈춘다.** 브라우저를 열어둔 채
   20초 이상 관찰해라
6. 로그아웃 후 그 쿠키로는 API가 401이다 (**DB 세션 행이 지워졌는지** 확인)
7. **대화를 열면 `conversation_reads`에 행이 생긴다.** D1을 직접 조회해라
8. **안읽음 배지가 사라진다**
9. 같은 대화를 다시 열어도 **행이 두 개가 되지 않는다**
10. 안읽음이 0인 대화를 열면 불필요한 요청이 안 나간다
11. 읽음 요청이 실패하면 배지가 되돌아온다
12. **사용자 A가 읽어도 B의 안읽음은 그대로다** (두 세션으로 확인)
